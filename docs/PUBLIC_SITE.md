# Публичный сайт (public_dir / public_upstream)

По умолчанию все пути вне транспортного API и моста отвечают встроенной
заглушкой. Релей может вместо этого раздавать настоящий сайт — тогда
«случайный гость» видит обычную страницу, а деплой релея маскируется.

Взаимоисключающие режимы (`public_dir` + `public_upstream` одновременно —
ошибка конфигурации; нужен `index.html`):

## static: `public_dir`

Сайт читается в память **при старте** (изменили файлы — перезапустите релей).

- GET/HEAD; Content-Type по расширению; ETag (SHA-256), `If-None-Match` → 304.
- Одиночный Range (`bytes=a-b`) → 206, некорректный → 416.
- `404.html` (если есть) отдаётся на промахи со статусом 404.
- Обход по путям (`../`, абсолютные) отвергается.
- `static_routes: legacy` — дополнительно extensionless-алиасы (`/about` →
  `/about.html`); по умолчанию `exact`.

## upstream: `public_upstream`

Стримящий обратный прокси на указанный origin (например `http://site:8080`).

- Оригинальные Host и путь сохраняются; hop-by-hop заголовки вырезаются;
  X-Forwarded-For — строго одно значение (как на всём релее).
- Ответ стримится (ResponseHeadersRead); обрыв клиента освобождает
  upstream-соединение.
- Ошибку 404 origin проходит как есть: приложение-владелец сайта само решает,
  что показывать.

## Где это уместно

`public_dir` — статический лендинг «прикрытия»; `public_upstream` — когда под
тем же доменом уже живёт настоящее приложение. Транспортные пути (`/api/v1/*`,
мост) приоритетнее сайта всегда.
